# Декомпозитор задач — расширение для Cursor

Боковая панель в Cursor: вставляете текст задачи, backend через LLM разбивает её на 3–5 подзадач,
вы правите план и копируете готовое задание для coding-агента. Рекомендуются только модели, которые вы отметили доступными.

Расширение работает с backend **finOps** (Go + PostgreSQL): <https://github.com/MusledPower/finOps>.
Никаких заглушек и демо-режима нет: любой запрос идёт на backend, а оттуда в LLM.

## Быстрый старт

Нужны Cursor и запущенный backend (его README: PostgreSQL → миграция → `go run ./cmd/api`).

1. Установите `task-decomposer-0.1.0.vsix`: `Ctrl+Shift+P` → **Extensions: Install from VSIX…**.
2. Откройте значок «Декомпозитор» в левой панели. Вверху панели видно состояние соединения.
3. Нажмите **«Задать токен»** и введите значение `API_BEARER_TOKEN` из `.env` backend. Токен хранится в SecretStorage Cursor.
4. Статус должен стать зелёным: «Backend доступен, токен принят». Введите задачу и нажмите «Разбить задачу».

Адрес backend по умолчанию `http://localhost:8080` (настройка `decomposer.apiBaseUrl`; вне localhost только `https://`).
Кнопка «Открыть в редакторе» (меню ⋯) показывает панель во всю ширину: ввод слева, план справа.

## Сборка из исходников

```bash
npm install
npm test            # тесты: настоящие HTTP-запросы к тестовому серверу, повторяющему поведение backend
npm run package     # соберёт task-decomposer-0.1.0.vsix
```
Отладка: открыть папку в Cursor и нажать F5 («Запуск расширения»).

## Настройки (Cursor → Settings → «Декомпозитор»)

| Настройка | Назначение |
|---|---|
| `decomposer.apiBaseUrl` | адрес backend, по умолчанию `http://localhost:8080` |
| `decomposer.requestTimeoutSec` | таймаут запроса, по умолчанию 100 с (backend ждёт LLM до 90 с) |
| `decomposer.models` | список моделей вашего coding-агента: `id`, `displayName`, `tier` (economy / balanced / premium), `notes` |

Модели по умолчанию: Claude Haiku 5.5, Sonnet 5.5, Opus 5.5. Если в вашем Cursor другие модели, замените список:
пользователь отмечает доступные в панели, backend проверяет, что LLM рекомендовала только их.
Backend передаёт LLM только `id`, `displayName` и `params`, поэтому класс и описание модели отправляются в `params`.

## Что умеет

- Ввод: текст задачи (обязательно), стек, критерии, ограничения, фрагмент кода, выбор моделей, предпочтение «Баланс / Качество / Стоимость».
- Состояния: пусто, загрузка (с отменой), план, ошибка. При ошибке ввод и предыдущий план сохраняются, повтор только вручную.
- Подзадача: название, цель, ожидаемый результат, критерии, зависимости, риск, рекомендуемая модель с пояснением («предварительно»). Всё редактируется; можно добавлять, удалять, переставлять.
- Проверка плана: обязательные поля, несуществующие и циклические зависимости, не больше 7 шагов. При ошибках копирование и экспорт заблокированы.
- Копирование отдельного задания (цель, критерии, ограничения, входы от зависимостей, контекст, список неизвестного) и всего плана; экспорт `.md` и `.json`.
- Один раунд уточняющих вопросов от модели.
- Ручные отметки «Выполнена / Не выполнена»; шаги с невыполненными зависимостями копируются только после предупреждения.
- Черновик и последний план сохраняются локально в Cursor; на сервер уходит только запрос на разбиение.

**Лимиты backend считаются в байтах UTF-8**, кириллица занимает 2 байта на символ: текст задачи до 10 000 байт (около 5 000 русских букв), критерии и ограничения вместе до 6 000 байт. Счётчики в форме показывают байты.

## Проверка по критериям приёмки (с настоящим backend)

| Сценарий | Как воспроизвести | Ожидание |
|---|---|---|
| Крупная задача | введите задачу на несколько абзацев (например, «Добавить экспорт отчёта в PDF с учётом фильтров, кнопку и тесты») | 3–5 подзадач с зависимостями, порядок исполнения, рекомендации моделей из вашего списка |
| Простая задача | «Исправить опечатку в подписи кнопки» | одна подзадача |
| Ошибка API | остановите backend (Ctrl+C в его окне) и нажмите «Разбить задачу»; либо введите неверный токен | карточка ошибки с причиной, ввод сохранён, кнопка «Повторить» |

Автоматически (`npm test`, 31 тест): запрос принимается тестовым сервером по правилам backend, разбор ответов
(в том числе `null` вместо пустых списков), все виды ошибок (401, 422, 500, 502, сеть, таймаут, отмена),
лимиты в байтах, проверка соединения, редактирование и копирование плана.

## Если что-то не работает

| Что видите | Причина |
|---|---|
| «Backend недоступен» | backend не запущен или неверный адрес/порт |
| «Backend не принял токен» | токен не совпадает с `API_BEARER_TOKEN` в `.env` backend |
| «Сервер не смог получить ответ от нейросети» | проверьте `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL` в `.env` backend |
| «Ошибка на сервере при сохранении плана» | не запущена база данных или не применена миграция |
| «Нейросеть вернула план, который не прошёл проверку» | модель ошиблась (например, предложила модель вне списка): нажмите «Повторить» |

## Структура

```
src/extension.ts        extension host: панель, токен, буфер обмена, экспорт
src/backend.ts          HTTP-клиент backend и проверка соединения
webview/src/            интерфейс (React + TypeScript), схема ответа (Zod), валидация плана, форматирование
tests/                  тесты и тестовый сервер, повторяющий поведение backend
```
